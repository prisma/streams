# O3 follow-up — one retained-interval policy

`ShardEngine::ring_read` and `ring_read_keyed` now delegate to one private `ring_read_selected` implementation. Selection changes which checked frames are returned; physical Db ownership, durable frontier, ring floor/ceiling, per-row density, structural admission, stored-byte accounting, consumed progress and witness construction follow one policy.

The existing entry points, counters and fallback behavior are retained. Filtered misses still count toward the scan budget and coverage witness. A partial covered interval remains usable; applied-only, evicted, malformed, foreign-owner and uncovered intervals do not gain a durability proof. The retirement handoff, transaction owner and retirement regressions are unchanged by this commit.

Executed validation: all six `reads_ring` tests, the separately selected O3 controls, and all-target Clippy. This local consolidation makes no new performance or remote-GET claim. The combined candidate still requires the follow-up screening decision, and PR #19 remains draft.
