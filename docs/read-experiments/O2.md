# O2: authenticated plaintext batch ownership

Experimental; performance and correctness acceptance pending. Control: O1 + O3 + O4 (`76d549a13cabc7507dc24fea88586492aaf2aa15`).

Uncompressed frames decrypt in place into one private batch buffer, reusing one AAD buffer. Planning reserves only the exact uncompressed prefix admitted by a cloned page budget. AEAD failure truncates tentative output. Metadata, record and plaintext admission precede creation of immutable record slices. Bounded partials expose only admitted records and retain the previous exact cursor behavior.

A read page carries an optional complete batch owner. Local outcomes propagate it; peer-decoded records have no such proof. Binary adapters transfer that owner only after checking every record's pointer, ordering and total length against it; otherwise they coalesce. Single-record binary responses share the record directly. JSON and segmented-newline responses reserve exact framing capacity and retain their existing bytes. Multi-batch/history-tail stitched results can still require coalescing.

Compressed records and over-limit candidates retain the existing authenticated, bounded decrypt/decompress fallback, including window and limit-plus-one checks. This first experiment does not eliminate allocations in that fallback. Buffers are request/batch owned; there is no shared mutable decryption or new cache. Retained capacity is bounded by the admitted plaintext prefix, with exact growth for the compressed fallback. Pending range metadata is temporary and must be included in allocation/peak-memory measurements.

New regressions verify stable payload/AAD allocations over 64 frames, rollback on authentication failure and withholding, one immutable owner across 64 exact payloads, partial-page progress, and retained-reader immutability. Existing format, corruption, compression-bomb, record/metadata, lifecycle, peer, JSON and resume tests remain gates.
