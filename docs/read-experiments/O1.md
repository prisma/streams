# O1 — retain checked frames and borrow routing metadata

Control: `dac9e908ec7bbf50d9b6479ce27991d198269bfb`. Status: experimental implementation; performance acceptance requires paired execution, not this note.

Canonical row and ring admission retain immutable `Bytes`, checked scalar metadata and validated ranges in `CheckedFrame`. Filtering, page decryption and absorption consume this representation. The single existing parser and stored-row validator remain authoritative; invalid nonmatching metadata still refuses progress and invalid ring entries still fall back to storage. Read headers borrow their routing key through the same generic header type used by owned write headers. Safe UTF-8 conversion when exposing a retained range remains explicit; it does not allocate or reparse scalar frame fields.

Page cipher lookup borrows routing keys on hits, allocating ownership on a miss. Version, stream-key, epoch and physical-segment boundaries and the 64 retained-cipher cap remain unchanged. Output records still own routing metadata required by their page contract. Checked metadata is not authentication: every delivered record still passes AEAD, including after structural admission of tampered ciphertext.

The existing transaction assertion adapts from String::as_str to its already-borrowed str without changing expected values. Cipher-cache cardinality checks sum the nested maps; all 128 lane/version bindings and the cap assertion remain. Additional tests exercise empty, short, Unicode and maximal keys, compressed/uncompressed frames, borrowed storage, exact metadata, nonmatching corruption and authentication refusal. No budget, frame format, nonce/key derivation, durability rule or historical gate baseline changes.

The retained metadata has a measurable memory cost; experiments must compare allocation/live-memory effects and complete-result latency before acceptance. Mechanism counters and raw measurements are maintained separately from shipping source.

Experiment completed: mechanism verified; performance acceptance remains limited as recorded in the [results](results.md) and [ledger](ledger.md). These notes describe the implementation, not a shipping-performance certificate.
