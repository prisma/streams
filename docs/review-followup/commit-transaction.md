# R03-A — one provisional commit transaction

Status: READY_FOR_REVIEW; source structure and execution remain subject to independent review.

`ShardEngine::commit_group` delegates to `CommitTransaction`, which owns one `WriteBatch`, one `DurableEffects` collection, the stream overlays, shared trim budget, and accounting/timing state. Its preparation phase expands bounded maintenance work and resolves every required accounting read before any command stages a write or provisional effect. Each ordered command temporarily takes its stream overlay and returns it before the next command. Producer/sequence, queue/configuration, billing, and frame accounting have distinct overlay components.

Append decision/loading and accepted-record staging are separate. Duplicate decisions still precede close, deferred-body, stream-sequence, and seal-fence checks. Logical close and fence remain direct typed operations; final-bearing appends retain their atomic close semantics. Queue configuration, complete checked state loading, bounded deletion, receive, and settlement have focused methods. Shared configuration-row loading replaces three duplicated read/decode paths. Queue snapshots remain transaction-owned until successful publication. Conservative generation fences can ratchet before a failed write, as required by the existing takeover/deletion protocol.

Finalization validates exact maintenance deltas and stages tail, dirty-index, billing, and maintenance rows. One write consumes the accumulated batch. Local success publishes applied state; the complete deferred effect owner then moves into the existing remote-WAL/dispatch barrier. No-write groups attach their replies to the prior applied group's barrier. Fence replies now use that same effect collection directly. Failure consumes the collection and replaces provisional successes/refusals together; the old helper accepting parallel reply vectors is deleted. Payload ingest observability moves only after write success. Ring frames transfer ownership into publication without cloning the frame list.

The 2,137-line transaction function is replaced by explicit owner phases and domain methods; the largest new production function is 160 lines. The old `commit_group` exception and the enlarged shard-file exception are removed. New units meet the default 200-line function/1,000-line file limits, with the original review baseline unchanged. Size is supporting evidence; the ownership and durability boundaries above are the structural correction.

`r03a_mixed_transaction_preserves_every_row_reply_and_publication` checks a group containing ordinary and final-bearing appends, logical close, fence, producer duplicate/refusal, configuration create/refusal, and an older-version billing acknowledgement. Required-read failure and injected group-write failure leave the complete key/value set unchanged and publish no provisional state. Success compares the entire row set, authenticates exact payloads and frame metadata, preserves newer billing debt, and checks all six append/close/fence replies, two queue replies, both tails/rings, usage, touches, and absorber signals across held dispatch. Random nonces and maintenance clock values are validated within their contracts rather than compared to invented constants. The write failure uses the existing group failpoint and the same rejection owner as an actual failed write.

This is a structural finding, not a claim that the previous implementation failed this preservation test. Original actual-WAL and held-dispatch tests, billing-read failure tests, producer/queue/absorption regressions remain required and unchanged. The portable final report identifies their execution revisions, raw outputs, and any failed fixture/compiler attempts; intermediate passing logs are not final-HEAD certification.
