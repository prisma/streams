# R06-A read-page contract

`application::read_budget::PageBudget` charges returned plaintext, routing-key metadata, and record count for segment reads, stitched forks, collection scans and peer decoding. Requested plaintext is clamped to 1 byte–8 MiB. A first record may exceed the request up to 32 MiB; once the payload allowance is exhausted, no further record is admitted. Subsequent records must fit the remaining allowance. A page also has at most 4,096 records and 1 MiB of conservative JSON metadata charges (`6 * routing_key_bytes + 128` per record). Routing keys retain their u16 byte-width limit.

Frame admission separately bounds the encoded record. Authentication precedes decompression. The decoder reads at most the remaining plaintext allowance plus one byte, and its zstd window is capped at 32 MiB. Exceeding the individual first-record limit is an error; a later record that crosses the remaining page allowance is withheld. The returned consumed offset stops immediately before that matching record, even when the storage scan fetched later records or proved later filtered misses. Applied reconnect positions remain clamped to durable watermarks.

Canonical storage legs examine an offset window of at most 4,096 positions. Stored-byte budgets also charge filtered misses; a first stored frame is allowed to cross the stored-byte budget, bounded by the encoded-record ceiling. History retains its eight-span planner and four concurrent fetches. Each span now charges every examined frame and retains its actual consumed position when stopping on a filtered miss. The existing sixteen-attempt absorption-race bound remains; a partial storage window is returned as partial rather than promoted to the full history frontier. These are per-request bounds, not a limit on aggregate memory across arbitrary concurrent requests. Existing service admission remains necessary.

The peer body ceiling is derived from the same contract: `4 * ceil(32 MiB / 3) + 1 MiB + 2048`. It covers base64, escaped routing metadata, record fields and the fixed page envelope, including a legal oversized first record. Both replay and physical-span scan receivers enforce that byte limit while streaming, cap the decoded record array before materializing a 4,097th object, and enforce the requested plaintext and metadata budgets after base64 decoding. Internal endpoints preserve small caller budgets rather than raising them to 4 KiB. Missing scan progress is rejected, including a missing `last` field where a present null value is legitimate.

Regression sources are `src/shard/read_budget_tests.rs`, `src/dst/tests/read_page_limits.rs`, `src/dst/tests/read_page_assembly.rs`, and `src/application/read_wire_tests.rs`. They exercise real SlateDB pages, compression enabled/disabled, ring and DB reads, postings-backed history/tail seams, exact filtered pagination, oversized-first-record progress, applied/durable positions, zero-sized records, match-free work limits, near-maximum keys, a decompression overrun, complete local/peer result equivalence, both real HTTP peer formats above the old 24 MiB cap, and declared receiver overflow before its held body arrives. The peer fixture seeds through the actual committer, frame encryption and remote WAL acknowledgement: the default ingress token bucket is intentionally outside this read test's scope.

All nine new regressions passed in the focused release run. Existing crypto (10), read (28), application read (4), history (26), postings (24), fork (14), and livefeed-history (11) filtered checks also passed; these filters overlap and are not a unique-test total. Final-revision execution status and raw receipts are recorded separately in the final follow-up report. The initial real-DB regression returned 14,516,224 plaintext bytes for a 65,536-byte request. Earlier fixture-only failures (private helper access, history flush setup, and unrelated ingress capacity) remain in the receipt bundle; they are not described as production read failures. These changes do not constitute independent cryptographic or production performance acceptance.
