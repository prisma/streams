# E03 — profiled read setup and bounded reuse

Status: performance comparison and owner acceptance pending; no latency budget or waiver is assumed.

Before changing the decrypt path, an isolated measurement build of a1c104d ran the existing eight complete-result workloads. ACTIVE-scoped wall timers measured the actual read segment-key HKDF, cipher construction, and AEAD decrypt calls. The 128 many-record replay requests made 8,192 calls to each stage: HKDF consumed 7.697% and cipher construction 2.218% of the summed request time (instrumented median 1.174 ms). The 128 hot filtered queries made 2,048 calls to each stage: 5.498% and 1.566% respectively (median 0.437 ms). The single-record replay shares were 0.233% and 0.067%. Timer overhead is included, and unmeasured time is not attributed to these mechanisms. A single process-cold sample establishes no tail distribution.

The resulting optimization retains at most 64 expanded cipher schedules in each segment read page. The cache binds the stream key, epoch, physical segment, routing key, and key version. It reuses lazy legacy/current schedules across mixed frames, preserving every AAD, nonce, authentication, and decompression limit. Additional distinct lanes retain only the already-existing compact subkey entry and decode through the uncached path. No state survives the page or belongs to another runtime. The expanded schedules occupy at most 129,024 bytes in the measured build, excluding the small boxed-pointer/map overhead; this is a bounded incremental allocation, not a claim about total request RSS. Read output, scan, metadata, and peer-wire limits are unchanged.

Two new tests exercise 128 distinct lanes, the 64-entry schedule cap, retries through cached/uncached lanes, segment/epoch/key-version fencing, mixed v2/v3/v4/v5 decoding, repeated use, tamper refusal, and identical decoded-byte limits. The existing page-budget, corruption, local/peer, and history regressions remain required. The receiver overflow fixture now checks that request bytes were actually read, satisfying Clippy without weakening its held-body assertion.

The portable final bundle contains the full profiler source, raw records, source/tree identity, binary/log hashes, normal benchmark source, and paired/interleaved final measurements. Profile timings above are diagnostic results, not the uninstrumented acceptance comparison. Final results must preserve all 64 KiB replay bytes and all 16 filtered matches across their complete pagination, and must retain zero product payload bridge copies. Local System-allocator/loopback measurements do not establish deployed Prisma Compute/Tigris latency, cost, or memory behavior. Workload-specific acceptance remains with the product owner; no threshold is manufactured from observed results.
