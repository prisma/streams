# R09-A — request maintenance ownership

Status: READY_FOR_REVIEW; engineering execution is not independent acceptance.

One runtime-owned `RequestWork` worker is registered directly with the existing critical-task supervisor. Its active futures, queue, and project/stream/epoch/kind coalescing map share one admission boundary: at most 8 active jobs, 64 queued jobs, and 72 retained keys. Every admitted job has a ten-second deadline, including queue residence. Callers hold result observers; dropping a request does not detach another task or cancel a shared job. Runtime shutdown drops the actual active operations, clears queued jobs/keys, and joins the worker. Separate runtime capabilities have independent owners and budgets.

Read, SSE, and append transition recovery use this owner. A refused, timed-out, or cancelled topology job preserves the descriptor's pending intent. A subsequent reader or an existing scaler hint can rediscover and retry it. This is not a claim that a restarted scaler scans the entire catalog automatically. An already-enqueued physical close remains the engine's durability responsibility, covered by R17-A; cancelling its result observer cannot manufacture a completed close.

TTL renewal uses the same queue and a fixed, incarnation-fenced expiry target. Reads wait after authorization and appends wait before append effects. Admission, timeout, and storage failures produce retryable HTTP 503 responses with Retry-After: 1 and `ttl_renewal_unavailable`. Cancellation invalidates descriptor caches, including ambiguous CAS completion. A replacement epoch cannot share or be mutated by an old job. A recent expiry needs no renewal.

Evidence in the portable final bundle will retain all attempts. `r09-red-executed.log` reproduces 160 retained detached TTL jobs and shutdown returning with an actual CAS still held. `r09-green-3.log` passes five regressions covering those mechanisms, independent runtimes, recreation fencing, actual HTTP overload/retry without append effects, and a held parent WAL close recovered exactly through a fresh reader. The topology fixture's earlier failed attempt pinned the parent to an unrelated shard; the corrected fixture materializes the same implicit parent route as production. Existing TTL, scaler, key-isolation, and SSE source tests pass; the `read_request` name filter selected zero tests and supplies no coverage. Architecture, source provenance, and the 441-test mapped inventory gates pass against the unchanged original baseline. Final clean-HEAD execution is recorded separately in the final report.
