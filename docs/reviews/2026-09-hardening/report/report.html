What the work amounts to

  • Fail-open verdicts became typed and fail-closed. Response or status sniffing, &'static str refusals, anyhow downcasts and Ok(None)-on-error were replaced by typed enums matched exhaustively, so a new or renamed refusal is a compile error rather than a silent 400/404/Ok(0). Items 21, 22, 30, 35, 49, 55, 57, 61, 65, 87, 27.
  • A topology or ownership transition may delay a caller but must never look like closure, absence or finality. Covered by bug #9 (stale-descriptor append), item 36 (descriptor cache generation), item 9 (fork-retained names judged at one instant), items 3/14/16 (watch and SSE ownership and engine incarnation), 34 (ring-member-only moves), 64 (phase-B refusal stays pending) and 63A (SeqCst custody handshake proven with Loom).
  • Liveness: silent hangs, spins and wedges became bounded waits, typed cutoffs or named failures. Items 4 (pull spin), 8 (absorber hold-and-wait), 15 (panicking single-flight), 17 (h1 head deadline), 33 and 86 (SSE retry/backoff, a 1.7M-reads-per-0.5 s spin), 11 and 12 (fleet tick and holdoff), and F-G (a TaskSupervisor::spawn teardown deadlock, reproduced deterministically after two CI hangs and fixed as their likely root cause).
  • Untrusted numbers and knobs now have owned ceilings, saturating arithmetic, and a refusal at boot instead of a wrap, panic or silent default. Items 10 (TTL), 24 (lease window), 25 (413 plus limit-posture validation), 41 (scaler cooldowns, TOKIO_WORKERS), 53 (SSE_H1_MAX_BUF, Stream-Seq length), 27 (byte-time overflow) and 32 (argv/env double parsing).
  • Quota and billing correctness: :scan and :pull are metered, clean rows are reconciled across every project, graceful stops flush read usage, rollups fail instead of re-merging or wedging, and sweep probes no longer escalate holdoffs. Items 5, 28, 26, 49, 12, 32, 27.
  • Tests that could not fail were made to bite, each with a recorded non-vacuity control. Items 20, 42, 66, 67, 73, 77, 80 and 92, the runtime_isolation fix exposed by item 57, and the F-H flake. Every fix landed red-first, and ten verbatim-move-then-fix pairs kept ceilinged files (product.rs, http.rs, billing.rs, registry.rs, history.rs, auth.rs, shard.rs, feed.rs) from growing; exception scopes recorded in commit bodies fell 1,019 -> 1,009, with more deleted afterwards.

Questions for the reviewer

These are the calls I would most like a second opinion on. Each one is expanded in the decision register below or in the ledger.

  1. Bug #7 (held): a month-boundary account re-stamp orphans the rollup SegmentState, so the carry bills both accounts every month. The designed fix re-keys persisted rollup state from segment/{account}/{project}/.. to segment/{project}/.. with an on-open migration (src/rollup/rekey.rs); once it runs, older binaries fail the carry closed. Should this land now, land only after a rehearsal on a copy of a real rollup DB (my recommendation), or be deferred until invoice export exists? Is a one-way persisted-layout migration acceptable at this release stage?
  2. F-G (714abcc2): is tasks/refusal.rs the right fix? It is a thread_local slot that sets aside a future dropped inside tokio::spawn by a closing runtime and drops it after the registration mutex is released. The alternative is to restructure TaskSupervisor::spawn so tokio::spawn never runs under that std mutex (e.g. reserve the registration, release the lock, spawn, then settle). Is the evidence enough to call the CI hang root-caused? The evidence is: a synthesized deterministic red (a_spawn_refused_by_a_closing_runtime_cannot_deadlock_its_supervisor); the original DST test never hung locally in 85+ runs; the hang struck twice in about 43 pushes, and 7 pushes have been green since.

Repository gate traps a maintainer should know (28)
  • The gate needs Python >= 3.11 (tomllib) but calls bare python3; the stock macOS 3.9 dies. Put a shim directory first on PATH with python3 -> /opt/homebrew/bin/python3.12. docs/RUST-QUALITY.md is normative (AGENTS.md points to it).
  • gate.sh writes its report to $OUT (environment variable, default /tmp/gate.txt), NOT to $1. It is fail-closed per stage: GATEFAIL-quality, -suite, -suite-ran, -capacity, -capacity-ran, then GATEDONE.
  • Files over 1,000 lines may not grow by ONE line compared with the push base. These include fleet.rs, history.rs, shard.rs, product.rs, http.rs, registry.rs, auth.rs, billing.rs and sse/feed.rs. DST test files are ALSO ceilinged: split them into a new #[path] module, add an owners.json by-path row and a src/dst/tests/README.md entry, and widen any mutation filter that named the old module (d93b421b created livefeed_engine_retired.rs for this reason). Doc edits must be line-neutral, or code must move out first in a pure verbatim-move commit. The next merge base lowers the ceiling to the new size.
  • A function-wide unwrap_used/expect_used #[expect] fingerprints EVERY path-call under it, so changing one call counts as 'accepted exception grew'. Scopes also ratchet scope_lines and syntax_facts. The ways out are: narrow the exception (move code out of the scope, as e6550142 did), or re-decide its reason text, which gives it a new identity. A tokio::spawn(async move {..}) under such a scope is ONE fingerprinted call-site and cannot be edited in place (spawn_load in d2e87129, the feed retry task in d902a85b, get_or_open's reaper in fd810688).
  • Fingerprints resolve import aliases. MOVING a callee to a new module changes the fingerprint of every ratcheted caller even when the caller's text is untouched (product_entry after product_scan moved). A verbatim-move commit can therefore fail the gate on its own: push it paired with the fix that re-decides the reasons, and say so in the message. A call through an absolute path does not move (fc18a704 re-exported spawn_telemetry). Keep types that ratcheted scopes name in place (CachedDesc stayed in registry.rs in ca36a7f4).
  • After DELETING an exception, run gate.py --prune; it needs a successful clippy build first. An unfulfilled #[expect] is denied, so shrinking a function under 100 lines forces deletion of its too_many_lines expectation (74391f9c, 796211d7, 6ef3bc64). The architecture gate now refuses obsolete budget exceptions (47799eb3): shrinking a function below its baseline makes its budget exception mandatory to delete (fb18840d, 6515a15d).
  • CI's mutation leg FAILS on ANY missed mutant (cargo-mutants exit 2, driver check=True) and has no disposition ledger. An equivalent mutant (e.g. < vs <= on elapsed()<ttl, | vs ^ on disjoint bit fields, rate > 0.0 vs >= 0.0) must be made killable, for example by extracting the predicate with an explicit now, or the code must be restructured or the redundant condition deleted.
