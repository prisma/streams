# Preview.7 OOM review (judge input — verify EACH item)

Context: single-instance A/B soak (project streams-ab21, fra) killed the
preview.7 slate binary at July-validated load (conc 128, ~360k ops) and
at conc 192 (~291k ops) — both ≈1 GiB accepted payload — while a
BILLING_METER=off arm died identically. Reviewer's verdict: history-L0 /
absorber backpressure amplified by process-wide memory-budget failures;
the new telemetry SlateDB DBs are NOT exonerated by the billing-off arm.

MUST-FIX CODE ITEMS:
1. ONE process-wide absorber memory budget: a shared weighted
   reservation (bytes + concurrent-gather cap) that every history gather
   acquires BEFORE reading and cloning frames; the reservation estimate
   must cover raw frames, WriteBatch values+keys, posting builders, and
   an SST-build multiplier. Default posture for a 1 GiB instance:
   32-64 MiB global bytes, 1-2 concurrent gathers. "32 MiB × however
   many shards are open" must be impossible.
2. Stagger absorber phases: each shard absorber's first tick seeded from
   the shard-prefix hash (like the WAL tick stagger), so co-opened
   shards do not become due and flush together.
3. Telemetry DBs get ONE small bounded cache/settings posture
   (TELEMETRY_CACHE_BYTES, 8-16 MiB default), applied to BOTH the read
   spool and the rollup DB. Neither may inherit SlateDB's per-DB
   defaults (512 MB-class cache, default L0/compaction posture).
4. Rollup off ingest instances: ROLLUP=1 runs on a designated instance,
   not competing with history compaction on ingestion VMs — documented
   as the deployment contract in staging/runbook/design docs.
5. Batch read-spool flushes: one drain round's sealed batches persist in
   ONE WriteBatch with ONE flush (not one flush per batch).
6. sweep_owned_outboxes must not permanently open every owned shard as a
   full engine: engines opened solely for telemetry debt are drained and
   deliberately closed (or replaced by a lightweight debt probe), while
   preserving traffic-independent debt discovery.
